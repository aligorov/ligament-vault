# Приёмка исправлений отказоустойчивости, 28 ноября 2026

Локальный пятиузловой стенд сохранил клиентское чтение и запись после каждого из десяти вариантов потери двух узлов. После последнего возврата совпали SHA-256 всех 11 подтверждённых файлов. Трёхузловая конфигурация из исходного аудита при потере двух узлов теряет большинство.

## Пятиузловая матрица

Пять голосующих участников etcd, PostgreSQL 16 с Patroni в strict-режиме и целевыми двумя синхронными репликами, пять логических ЦОД SeaweedFS с размещением `200`. Перед каждой инъекцией проверялись работа всех пяти узлов и доступность контрольного файла. Клиент проверял CA и имя `files.audit.test`, читал исходные 128 КиБ, записывал новый файл и сверял SHA-256 после скачивания.

Отдельное отключение узла с активным FTPS и лидерами PostgreSQL и SeaweedFS заняло 84,84 с до конца проверки. После восстановления в PostgreSQL зарегистрированы четыре streaming-реплики, из них две sync. В физическом срезе после возврата пары 2 + 3 каждый из 23 томов бакета имел три копии. При потере пары 4 + 5 дополнительный клиент успел перечитать и проверить десять прежних файлов, пока работали три узла.

Каждая пара проверена один раз на одном Docker-хосте. Для этой матрицы DNS-алиас переключался вручную, один HAProxy оставался доступным, роли SeaweedFS были объединены на каждой логической ноде. Интервал в таблице включает все файловые операции и повторные попытки клиента. Публичная DNS-зона и сеть между физическими площадками в замер не входили.

## Отдельные сквозные проверки

| Подсистема | Проверенный результат |
|---|---|
| Автоматический DNS | Два SFTPGo, один общий SeaweedFS, штатный daemon арбитра, авторитетный dnsmasq с TTL 1 с. После остановки активного edge обычный клиент прочитал прежние 65 536 байт через FTPS по тому же FQDN за 56,666 с от остановки. Новые 32 768 байт записались и прочитались. При потере общего S3 клиентская проба вернула ошибку. В этом стенде моделировались SSH-команды записи lease и fencing. |
| Ошибка провайдера и failback | На ответ 503 арбитр сохранил прежнее опубликованное состояние. После подтверждения провайдером записал новое. Регрессионные тесты охватывают перезапуск между публикацией и SQLite commit, отставание WAL и расхождение timeline. |
| HAProxy | Замена адреса backend под прежним FQDN прошла без reload. Первое проверенное соединение в одном локальном прогоне установилось за 2,394 с. |
| Добавление и замена | На реальном etcd с mTLS проверены 3→4→5, повторное добавление и продвижение learner, замена участника с другим DNS и ID. Два потерянных участника из пяти оставили кластер доступным для записи. Попытка остановить ещё одного живого участника отклонена. Проверены переходы membership SeaweedFS. |
| Старые тома | При цели `200` строгая проверка обнаружила тома `100` и тома с меткой `200`, но двумя реальными копиями. После изменения политики и ремонта подтверждены девять томов в трёх ЦОД. Исходный файл прочитан с третьего диска после потери двух первых. |
| PostgreSQL | На действующем кластере `sync-config` перевёл реплику из async в sync и обратно. Цель 2 при одной доступной реплике отклонена с сохранением прежнего состояния. Отдельно установлено, что Patroni 3.3 может уменьшать фактическое число sync-реплик при потере кандидатов. |
| Журнал клиентов | Для изоляции сбоя журнала SFTPGo использовал локальную БД учётных записей, сборщик писал в отдельный PostgreSQL. Реальные операции SFTP дали девять строк в `postgres.public.client_events` — три входа, три отказа, две загрузки и одно скачивание. После остановки PostgreSQL, перезапуска сборщика и возврата БД очередь опустела. После удаления SFTP-узла и повторного запуска сборщика в БД осталось девять строк. Утрата диска с ещё не отправленной очередью остаётся окном потери журнала. |
| Внешний S3 и публикация | Независимый локальный S3 с HTTPS и SigV4. Прерывание проверяемой SFTP-публикации сохранило прежние 65 536 байт по конечному имени. Повтор опубликовал 16 МиБ с проверенным SHA-256. Для прямого SFTP без ожидаемого размера сохраняется риск укороченной загрузки. |
| Восстановление | Холодное восстановление физических томов вернуло 131 072 байта с исходным SHA-256, VersionId и COMPLIANCE. Удаление защищённой версии вернуло HTTP 403, объект, созданный позднее выбранной точки, вернул 404. HMAC отверг подменённый блок. Отдельная проверка pgBackRest подняла PostgreSQL на новом сокете ровно на именованной WAL-точке. Восстановление внешних клиентских бакетов выполняет их провайдер. |

## Условия эксплуатации и повтор

Конфигурация, версии и секреты хранятся в SQLite контроллера. Секреты зашифрованы age, для восстановления нужны база и ключ. Выполнены проверки первого импорта, повторного запуска, конкурентного изменения, восстановления с ключом и изоляции БД арбитра. Приложения получают штатные конфигурационные файлы. Адаптер ACME lego передаёт в `*_FILE` только пути временных файлов с учётными данными из БД.

Из корня проекта можно повторить проверку арбитра и протоколов командой `python3 tests/integration/dns_failover.py`. Команды настройки, восстановления и перевода старых томов на три копии приведены в [README](../README.md).

Полный штатный `ligactl scale add / replace` на вложенных Ubuntu с чистым шестым VPS добавлен в ручной сценарий CI `scale_ha`. Этот сценарий локально не запускался из-за свободного места на диске. Проверены CLI dry-run, компоненты на реальных сервисах, синтаксис задания и матрица локальной валидации. Гипервизоры Multipass и Lima здесь отсутствуют. Испытания облачного DNS-провайдера и публичного S3 не проводились по выбранному локальному объёму проверки.
